# 05 State Persistence

## Goal

Show how to persist structured `AgentState` across agent invocations using a checkpointer and stable `thread_id`.

## What changed from Lab 03

Lab 03 passed custom state into a single invocation.

That state was structured, but it was not persisted across turns.

This lab introduces framework-native persistence:

```python
checkpointer=MemorySaver()
```

and a stable thread identity:

```python
config = {
    "configurable": {
        "thread_id": "learning-state-demo"
    }
}
```

## Why persistence matters

Without persistence, state disappears between invocations.

Production agents need to persist:

- User preferences
- Workflow progress
- Completed steps
- Tool results
- Session state

## Expected behaviour

The exact assistant wording may vary because the response is generated by the local Ollama model.

The important behaviour is:

- Step 1: State is saved under a `thread_id`
- Step 2: The same `thread_id` loads the persisted state automatically
- The assistant answers using the loaded persisted state

## Learning point

AgentState is useful for structured state during one invocation.

Persisted AgentState is useful across invocations.

A checkpointer stores state between calls so the agent remembers structured data without resending message history.
