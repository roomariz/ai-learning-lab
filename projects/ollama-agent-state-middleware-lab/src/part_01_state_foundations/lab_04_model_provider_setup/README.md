# 04 Model Provider Setup

## Goal

Set up a clean model-provider switch.

The project remains local-first with Ollama, but it can also support OpenRouter later without changing the lab files.

## Why this matters

A learning repo should be easy to run locally.

A production-style repo should also avoid hard-coding the model provider inside every lab.

This lab moves provider selection into shared configuration.

## Supported providers

```txt
ollama
openrouter
Default setup

The default provider is Ollama:

MODEL_PROVIDER=ollama
OLLAMA_MODEL=qwen2.5-coder:7b
OLLAMA_BASE_URL=http://localhost:11434
Optional OpenRouter setup

To use OpenRouter later:

MODEL_PROVIDER=openrouter
OPENROUTER_API_KEY=your_api_key_here
OPENROUTER_MODEL=openai/gpt-4o-mini
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
Files in this lab
src/04_model_provider_setup/
├── README.md
├── main.py
└── expected_output.txt

This lab also updates:

src/common/config.py
src/common/model.py
.env.example
pyproject.toml
Run
uv sync
uv run python -m src.04_model_provider_setup.main
Expected behaviour

The exact assistant wording may vary because the response is generated by the selected model.

The important behaviour is:

The config prints the selected provider.
With MODEL_PROVIDER=ollama, the project uses the local Ollama model.
With MODEL_PROVIDER=openrouter, the project requires OPENROUTER_API_KEY.
Lab files no longer need to know which provider is being used.
Learning point

Model setup belongs in shared configuration.

Individual labs should ask for a chat model, not hard-code a provider.
