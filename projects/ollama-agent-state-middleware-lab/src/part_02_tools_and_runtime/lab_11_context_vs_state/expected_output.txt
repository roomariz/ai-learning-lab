EXPLANATION:
Context vs State distinction:
CONTEXT (stable, constant):
  {'user_id': 'learner-001', 'role': 'learner', 'tenant_id': 'learning-lab', 'environment': 'local'}

STATE (mutable, changes):
  learner_name: Muhammad
  current_topic: context_vs_state
  tool_call_count: 0
  notes: 1
  completed_topics: 6

Conclusion
==========

Context vs State distinction:

STATE (AgentState) - Mutable:
- Changes during conversation
- Fields: learner_name, notes, current_topic, tool_call_count
- Tools modify via Command(update={...})
- Access via runtime.state in tools

CONTEXT (RUN_CONTEXT) - Stable:
- Constant throughout the run
- Fields: user_id, role, tenant_id, environment
- Passed separately to seed prompts
- Not automatically in runtime.state

Key insight:
  state = changing data (in AgentState)
  context = stable run metadata (separate dict)
