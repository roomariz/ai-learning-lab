Conclusion
==========

Tools can read state to make informed decisions without changing it.
This lab demonstrates read-only access to state through ToolRuntime:
- @tool decorator registers tools for the agent
- ToolRuntime is injected by the framework
- runtime.state reads current state (no writes in this lab)
- authorised_tools in state controls tool access at runtime
- MemorySaver + thread_id persist state across invocations

Read-only tools are useful for profile checks, progress checks, permission checks, and routing decisions.

Lab 10 will cover writing state through Command(update={...}).
