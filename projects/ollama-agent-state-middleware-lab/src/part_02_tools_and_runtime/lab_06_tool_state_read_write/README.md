# 06 Tool State Read Write

## Goal

Show how tools can read from and write to structured `AgentState` using framework-native patterns.

## What changed from Lab 05

Lab 05 introduced persistence with `MemorySaver` and a stable `thread_id`.

This lab adds tools that interact with persisted state:

1. A read tool reads the learner's current status through `ToolRuntime`.
2. A write tool adds a learning note using `Command(update={...})`.
3. Another write tool marks the current topic as complete using `Command(update={...})`.

## Why this matters

Tools are not only for external APIs.

In production agents, tools often need to inspect and update state.

For example, a tool may need to:

1. Check the current workflow step.
2. Read the user's permissions.
3. Add a note.
4. Mark a task as complete.
5. Store a tool result.
6. Update the next topic or next action.

## Framework pattern

This lab uses the framework-native pattern:

```python
@tool
def read_learning_status(runtime: ToolRuntime) -> str:
    state = runtime.state
```

and for state updates:

```python
return Command(
    update={
        "notes": updated_notes,
        "messages": [
            ToolMessage(
                content="Note added",
                tool_call_id=runtime.tool_call_id,
            )
        ],
    }
)
```

`ToolRuntime` is injected by the framework. It is hidden from the LLM.

## Expected behaviour

The exact assistant wording may vary because the response is generated by the local Ollama model.

The important behaviour is:

- Initial state contains learner profile and progress.
- The first tool reads from state via `runtime.state`.
- The second tool writes a note using `Command(update={...})`.
- The third tool marks `tool_state_read_write` as completed using `Command(update={...})`.
- Final state shows the updated note, completed topic, current topic, and last action.
- All state access uses ToolRuntime (injected by framework, not manual).

## Learning point

Tools can now read from and write to persisted state using framework-native patterns.

This sets the foundation for understanding how tools interact with state in production agents.
