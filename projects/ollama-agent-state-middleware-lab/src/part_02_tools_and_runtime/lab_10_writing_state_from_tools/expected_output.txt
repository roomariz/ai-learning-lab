Conclusion
==========

Writing tools intentionally change state through Command(update={...}).
This lab demonstrates write access to state:
- @tool decorator registers tools for the agent
- ToolRuntime is injected by the framework
- Command(update={...}) returns updates to apply to state
- ToolMessage records the tool invocation in messages
- authorised_tools in state controls tool access at runtime
- MemorySaver + thread_id persist state across invocations

The key pattern for writing state:
    return Command(
        update={
            "field": new_value,
            "messages": [ToolMessage(content="...", tool_call_id=runtime.tool_call_id)],
        }
    )

Write tools are useful for adding notes, completing tasks, setting state, and persisting results.

Lab 09 was read-only; Lab 10 is write-focused.
