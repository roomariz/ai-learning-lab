# 05 State Persistence

## Goal

Show how to save and load structured agent state.

## What changed from Lab 03

Lab 03 used custom state in memory only.

That state existed while the program was running, but it was not saved anywhere.

This lab saves the state to a JSON file:

```txt
data/state/learning_state.json

The program then loads that file again and uses it in a later step.

Why persistence matters

Without persistence, state disappears when the process ends.

Production agents often need to persist:

User preferences.
Workflow progress.
Completed steps.
Tool results.
Review status.
Session state.

Expected behaviour

The exact assistant wording may vary because the response is generated by the local Ollama model.

The important behaviour is:

The program loads existing state if the JSON file exists.
If no JSON file exists, it creates initial empty state.
The program updates the state for Lab 05.
The program saves the state to data/state/learning_state.json.
The program loads the saved state again.
The assistant answers using the loaded persisted state.
Learning point

State is useful during one run.

Persisted state is useful across runs.

A production agent should not depend only on message history for important facts that must survive beyond the current call.
