20 Middleware Execution Order
=============================

Scenario 1: Normal flow
-------------------------

[logging] before
[validation] passed
[authorisation] passed
[tool] running add_note
[logging] after

RESULT:
note added: buy groceries

NOTES:
['buy groceries']

Scenario 2: Validation blocks
-------------------------------

[logging] before
[validation] blocked
[logging] after

RESULT:
Blocked before running add_note

NOTES:
['buy groceries']

Scenario 3: Authorisation blocks
----------------------------------

[logging] before
[validation] passed
[authorisation] blocked
[logging] after

RESULT:
Blocked before running delete_all

NOTES:
['buy groceries']

Scenario 4: Tool crashes, error handler catches
-------------------------------------------------

[logging] before
[validation] passed
[authorisation] passed
[tool] running risky_note
[error handler] caught ValueError
[logging] after

RESULT:
Error (ValueError): invalid note: correct input

NOTES:
['buy groceries']

Conclusion
----------

Middleware execution order determines system behaviour.
Validation must run before authorisation before tool execution.
Error handling wraps risky execution, and logging wraps everything.
Order matters. Same middleware, different order, different outcome.
